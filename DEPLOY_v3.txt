[ 목적 ]

  이 문서는 현재 머신에서 검증된 데이터 수집 결과와 평가 파이프라인을 다른
  머신으로 그대로 옮겨 동일하게 테스트하기 위한 절차다.

  - Cohesity로 올라가는 실데이터는 gaia_dataset(DART)과 gaia_web_dataset(Web)
    두 개뿐이며, 각각 tar로 묶어서 이동한다.
  - 코드(gaia_ragas, collector/eval 등)는 타겟 머신에 인터넷이 되므로
    rsync 대신 **git clone**으로 가져온다.
  - 실제 테스트(QA 생성 + Cohesity GAIA API 평가)는 타겟 머신에서
    gaia_ragas(DART용) / collector/eval(Web용) 두 파이프라인으로 수행한다.
  - qdrant_rag(로컬 벡터 검색 RAG)는 이번 이전 범위에서 제외한다.


[ 이동 대상 정리 ]

  ■ Cohesity에 올릴 데이터 (tar로 묶어 이동 — git에는 안 잡히는 대용량 데이터)

    gaia_dataset/       ← DART 통합 데이터셋 (현재 103GB, XML/PDF/XLS 원본, 275개 회사)
    gaia_web_dataset/   ← Web 수집 데이터셋 (현재 60GB, PDF/DOCX/XLSX/PPTX 등, 73개 소스)

  ■ 타겟 머신에서 git clone으로 가져올 코드

    저장소: https://github.com/woohwan/cohesity-poc.git (branch: main)

    clone 하면 repo 전체(qdrant_rag/, collector/gaia_kr_collector/ 포함)가
    다 딸려오지만, 실제로 쓰는 건 이 두 곳뿐이다:
      gaia_ragas/         ← DART 데이터 QA 생성 / GAIA·RAGAS 평가
      collector/eval/     ← Web 데이터 QA 생성 / GAIA·RAGAS 평가

  ■ 이번엔 쓰지 않음 (clone은 되지만 셋업/실행 안 함)

    qdrant_rag/                    로컬 RAG 인제스트/검색 테스트 — 이번 범위 아님
    collector/gaia_kr_collector/   Web 데이터는 이미 수집 완료본을 tar로 옮기는
                                    것이라 수집기 자체는 불필요
                                    (타겟에서 재수집이 필요해지면 별도 안내 참고)

  ※ gaia_dataset/, gaia_web_dataset/ 은 .gitignore에 잡혀있어 git clone으로는
    안 온다 — 반드시 tar+Cohesity로 별도 전달해야 함.
  ※ .venv/, output/ 은 타겟에서 재생성 (git에도 안 잡힘)
  ※ gaia_ragas/config.py의 GAIA_DATASET_DIR, collector/eval/config.py의
    DATASET_DIR은 둘 다 자기 상위 디렉터리를 기준으로 형제 폴더를 상대경로로
    찾는다. clone한 repo 루트에 tar를 그대로 풀면 자동으로 맞는 위치가 된다:
      cohesity-poc/gaia_ragas/       ↔  cohesity-poc/gaia_dataset/
      cohesity-poc/collector/eval/   ↔  cohesity-poc/gaia_web_dataset/


[ 1. 소스 머신 — tar로 묶기 ]

  cd /data/richard/cohesity-poc

  tar -cf gaia_dataset.tar gaia_dataset/
  tar -cf gaia_web_dataset.tar gaia_web_dataset/

  ※ 압축(-z) 없이 tar만 뜬다 — 이미 PDF/XLSX 등 압축률 낮은 바이너리 위주라
    -z를 걸어도 시간만 오래 걸리고 용량은 크게 안 줄어듦. 필요하면 -z 추가.
  ※ gaia_web_dataset은 수집기가 계속 돌고 있으면 tar 뜨는 시점 기준 스냅샷이
    된다 — 뜨기 직전에 아래로 잠깐 멈추는 걸 권장:
      cd collector/gaia_kr_collector && ./run.sh stop


[ 2. Cohesity에 업로드 / 보호 ]

  tar 파일 2개를 Cohesity가 백업 대상으로 인식하는 위치(NAS/SMB/NFS 공유,
  또는 에이전트가 설치된 VM 디스크)에 올려둔다.

  이후 Cohesity 콘솔에서:
    1. 해당 소스(Source) 등록
    2. Protection Group 생성 후 tar 파일 포함해 백업 수행
    3. 타겟 머신에서 필요할 때 Recover/Clone으로 복원

  (Cohesity 쪽 세부 조작 절차는 이 문서 범위 밖 — 운영 가이드 별도 참고)


[ 3. 타겟 머신 — 코드 clone ]

  cd /data/cohesity-poc   # 또는 원하는 위치
  git clone https://github.com/woohwan/cohesity-poc.git .

  ※ private repo면 타겟 머신에 GitHub 인증(SSH 키 또는 HTTPS PAT)이
    미리 설정돼 있어야 함.
  ※ 이미 다른 경로에 clone돼 있으면 git pull로 최신화만 해도 됨.


[ 4. 타겟 머신 — 데이터 복원 및 압축 해제 ]

  # Cohesity에서 복원받은 tar 파일이 clone한 repo 루트에 있다고 가정
  cd /data/cohesity-poc
  tar -xf gaia_dataset.tar
  tar -xf gaia_web_dataset.tar

  # 압축 해제 후 최상위 구조가 아래와 같아야 함
  #   /data/cohesity-poc/gaia_dataset/...
  #   /data/cohesity-poc/gaia_web_dataset/...


[ 5. 타겟 머신 — 환경 설정 ]

  # Python 3.12 필요 (두 가상환경 모두 3.12로 검증됨. 3.10+면 동작하나 미검증)
  # 시스템 python3 버전에 안 좌우되게 Miniconda로 정확한 버전을 받는다 —
  # 배포판/권한(root 불필요) 안 가림.

  # Miniconda 설치 (이미 설치돼 있으면 건너뜀 — `conda --version`으로 확인)
  wget -O ~/miniconda.sh https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh
  bash ~/miniconda.sh -b -p $HOME/miniconda3
  source $HOME/miniconda3/bin/activate
  conda init bash   # 이후 새 셸부터 conda 명령 바로 사용 가능 (재로그인 필요할 수 있음)

  # Python 3.12 환경 생성 및 활성화
  conda create -n cohesity-poc python=3.12 -y
  conda activate cohesity-poc
  python3 --version   # 3.12.x 로 나오면 정상

  ※ 새 터미널 세션을 열 때마다 `conda activate cohesity-poc`를 다시 해줘야
    conda의 python3.12가 잡힌다 — 안 하면 시스템 기본 python3로 venv가
    생성될 수 있으니 주의.

  # gaia_ragas 가상환경
  cd /data/cohesity-poc/gaia_ragas
  python3 -m venv .venv
  .venv/bin/pip install --upgrade pip
  .venv/bin/pip install -r requirements.txt

  # collector/eval 가상환경
  cd /data/cohesity-poc/collector/eval
  python3 -m venv .venv
  .venv/bin/pip install --upgrade pip
  .venv/bin/pip install -r requirements.txt


[ 6. 테스트 실행 ]

  export ANTHROPIC_API_KEY=sk-ant-...
  # Cohesity GAIA API (evaluate 단계에 필요 — Helios: Settings > Access
  # Management > API Keys 에서 생성)
  export COHESITY_CLUSTER_URL=https://<helios-fqdn>
  export COHESITY_API_KEY=<api-key>
  export COHESITY_DATASET_NAME=<dataset-name>

  # ── DART 데이터 (gaia_ragas) ──────────────────────────────────
  cd /data/cohesity-poc/gaia_ragas
  ./run.sh --step sample
  ./run.sh --step qa
  ./run.sh --step testset
  ./run.sh --step evaluate        # Cohesity GAIA 클러스터 호출 + RAGAS 채점

  # 특정 회사만 (예: 삼성전자)
  ./run.sh --step sample --company 삼성전자
  ./run.sh --step qa     --company 삼성전자

  # ── Web 데이터 (collector/eval) ───────────────────────────────
  cd /data/cohesity-poc/collector/eval
  .venv/bin/python run_pipeline.py --step sample
  .venv/bin/python run_pipeline.py --step qa
  .venv/bin/python run_pipeline.py --step testset
  .venv/bin/python run_pipeline.py --step evaluate

  # 문서 타입별 또는 수집 소스(=토픽)별로 지정도 가능
  .venv/bin/python run_pipeline.py --step all --type pdf
  .venv/bin/python run_pipeline.py --step all --group-by source --source bok_publications
